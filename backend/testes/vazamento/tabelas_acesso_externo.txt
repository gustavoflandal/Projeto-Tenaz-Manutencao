# Tabelas e comandos que um escopo externo (prestador, locatario, link)
# alcança — a lista fechada da seção 2.9.4 de docs/2_ARQUITETURA_BANCO_DADOS.md
# e da seção 6.6 de docs/5_ARQUITETURA_SOFTWARE.md.
#
# A suíte calcula, a partir das policies do catálogo, quais comandos de cada
# tabela NÃO estão travados por uma restritiva app.escopo_interno() para o
# tenaz_app, e compara com este arquivo. Divergência nos dois sentidos quebra
# o build: tabela nova aberta a externo sem passar por aqui, ou linha daqui que
# o banco não confirma.
#
# Um comando de escrita para externo é exceção e precisa dizer qual linha a
# policy deixa gravar. DELETE por escopo externo não existe hoje: o WITH CHECK
# não alcança o DELETE, e toda tabela com leitura externa precisa da
# restritiva escopo_externo_exclusao (seção 2.9.4).
#
# Formato: esquema.tabela  COMANDOS(separados por vírgula, na ordem SELECT,INSERT,UPDATE,DELETE)  # justificativa

app.empresa           SELECT         # cadastro da contratante (nome, fuso) para os quatro escopos; não altera nem apaga
app.unidade           SELECT         # leitura para os quatro escopos (seção 2.9.4); não grava nem apaga
app.pessoa            SELECT         # prestador: pessoas do seu fornecedor; prestador e locatário: pessoas dos usuários que enxergam
app.usuario           SELECT,UPDATE  # vê a si e aos colegas do mesmo fornecedor ou locatário; altera só a própria linha, sem trocar o vínculo e só nome e telefone (trg_usuario_colunas_externo, ISO-E01-01); INSERT travado no interno (escopo_externo_insercao)
app.evento_auditoria  INSERT         # o trigger grava o evento na transação do externo; leitura só interna
